Content Architecture

All content is stored as static JSON files fetched at runtime — the platform needs no server-side code.

Two files control everything manifest.json is the catalog — it lists all subjects and topics. Individual topic files contain the actual educational content as an array of typed blocks. 
frontend/public/content/
├── manifest.json                        ← subject catalog (one file)
└── subjects/
    ├── linear-algebra/
    │   ├── vectors.json                 ← one topic per file
    │   └── matrices.json
    ├── calculus/
    │   ├── derivatives.json
    │   └── derivative-rules.json
    └── data-science/
        └── distributions.json

Topic files are fetched on demand when a learner opens a topic — they are never bundled into the JavaScript build. You can add new files and update manifest.json without restarting anything (in dev mode) or rebuilding (in production, the dist/ folder's static files can be updated independently).

Adding Content: Step by Step
  • 1
    Generate the topic JSON

    Use docs/topic-schema.md as a system prompt. Ask the LLM: "Generate a Rota topic JSON file about [subject]. Cover [concepts]. Include at least one of each block type."

  • 2
    Save the topic file

    Place it at frontend/public/content/subjects/<subject-id>/<topic-id>.json

  • 3
    Update the manifest

    Open frontend/public/content/manifest.json. Append to the subject's topics[] array (or add a new subject entry to subjects[]).

  • 4
    Refresh the browser

    No rebuild needed. The dev server (npm run dev) serves public/ as static files. The new topic appears immediately.

Block Types Reference

Every topic is an ordered array of blocks. Each block has a "type" field; the remaining fields depend on the type.

text Prose & HTML Explanations, definitions, transitions
JSON
{
  "type": "text",
  "content": "<p>A <strong>vector</strong>
  has magnitude and direction.
  A <em>scalar</em> has only
  magnitude.</p>
  <h3>Notation</h3>
  <ul>
    <li>2D: <code>[x, y]</code></li>
    <li>3D: <code>[x, y, z]</code></li>
  </ul>"
}
Rendered

A vector has magnitude and direction. A scalar has only magnitude.

Notation

  • 2D: [x, y]
  • 3D: [x, y, z]

Allowed HTML tags: p br strong em b i h2 h3 h4 ul ol li code pre blockquote a span

math LaTeX / KaTeX Equations and formulas
JSON
{
  "type": "math",
  "display": true,
  "content": "f'(x) = \\lim_{h \\to 0}
    \\frac{f(x+h) - f(x)}{h}"
}
Rendered
f'(x) = limh→0 [f(x+h) − f(x)] / h
FieldNotes
contentLaTeX — double-escape backslashes in JSON
displaytrue = centred block (default); false = inline

plot Plotly.js Figure Interactive 3D, scatter, surface — lazy loaded
JSON
{
  "type": "plot",
  "height": 400,
  "plotData": [
    {
      "type": "scatter",
      "mode": "lines",
      "x": [-3, -2, -1, 0, 1, 2, 3],
      "y": [9, 4, 1, 0, 1, 4, 9],
      "name": "x²",
      "line": { "color": "#4f46e5", "width": 2 }
    }
  ],
  "layout": {
    "title": "f(x) = x²",
    "xaxis": { "title": "x" },
    "yaxis": { "title": "f(x)" }
  }
}

Use standard Plotly.js trace types: scatter bar heatmap surface contour histogram. The chunk is loaded lazily (≈4.6 MB) so it doesn't affect initial page load.

visualization Custom React Component Interactive named components from the registry
JSON
{
  "type": "visualization",
  "component": "VectorSpace2D",
  "props": {
    "interactive": true,
    "vectors": [
      { "x": 3, "y": 1, "color": "#4f46e5", "label": "a" },
      { "x": 1, "y": 3, "color": "#10b981", "label": "b" }
    ]
  }
}

Registered components

componentPropsDescription
VectorSpace2D vectors: [{x, y, color?, label?}]
interactive: boolean 		2D grid with draggable vector arrows. Shows sum vector when 2+ vectors are provided.
FunctionPlot fnName: string
domain: [min, max]
range?: [min, max]
color?: string
label?: string 		SVG function plot. Valid fnName values: sin cos tan x^2 x^3 exp ln sqrt abs

To add a new component: create src/visualizations/MyViz.jsx and register it in src/visualizations/registry.js.

embed Sandboxed iframe Standalone HTML simulations
JSON
{
  "type": "embed",
  "src": "/content/subjects/physics/pendulum.html",
  "height": 500,
  "title": "Pendulum simulation"
}

The HTML file must be placed in frontend/public/content/subjects/<subject>/. The iframe is sandboxed with allow-scripts allow-same-origin. Use for p5.js sketches, THREE.js scenes, or any custom simulation that can't be expressed as a React component.

quiz Multiple-Choice Quiz Knowledge check with instant feedback
JSON
{
  "type": "quiz",
  "question": "What is d/dx[x³]?",
  "options": [
    "x²",
    "3x²",
    "3x³",
    "x⁴/4"
  ],
  "answer": 1,
  "explanation": "Power rule: nxⁿ⁻¹ → 3x²"
}
⚠ answer is a zero-based index In the example, "answer": 1 means the second option ("3x²") is correct.

Manifest Schema

The manifest is the single source of truth for what subjects and topics exist. It is fetched once and cached for the session.

New subject entry

{
  "id": "subject-id",            // kebab-case, unique
  "title": "Subject Title",
  "description": "One sentence shown on the catalog card.",
  "icon": "📐",                  // emoji or short string
  "theme": {
    "primary": "#4f46e5",
    "accent":  "#818cf8",
    "bg":      "#eef2ff"
  },
  "topics": [
    {
      "id": "first-topic",
      "title": "First Topic",
      "file": "subject-id/first-topic.json",
      "estimatedMinutes": 20
    }
  ]
}

Adding a topic to an existing subject

Append to the subject's topics[] array:

{
  "id": "new-topic",
  "title": "New Topic Title",
  "file": "subject-id/new-topic.json",
  "estimatedMinutes": 15
}

Quality Guidelines

Pedagogical structure

  • Open each topic with a plain-English definition before any formulas
  • Introduce notation gradually — never use a symbol without defining it first
  • Alternate block types — avoid 3+ consecutive text or math blocks
  • Include 2–4 quiz blocks per topic, distributed throughout (not clustered at the end)
  • Use chart for discrete comparisons, plot for continuous/scientific data, visualization for intuition building

Field constraints

FieldConstraint
All id fieldsLowercase letters, digits, hyphens only — no spaces or underscores
quiz.answerZero-based index into options[]
quiz.options2–4 items; keep each under ~60 characters
math.contentDouble-escape backslashes in JSON: \\frac not \frac
chart.data[].nameKeep ≤ 15 characters so axis labels don't overlap
visualization.componentMust exactly match a key in registry.js

Suggested LLM system prompt

You are generating educational content for Rota, a browser-based learning
platform. Content is stored as JSON files where each topic is an ordered
array of typed blocks.

Refer to docs/topic-schema.md for the exact JSON schema, all block types,
field constraints, and a complete worked example.

When generating a topic:
- Start with a plain-English explanation before any math
- Use at least 3 different block types
- Include 2-4 quiz blocks distributed throughout
- Double-escape all LaTeX backslashes (\\frac, not \frac)
- quiz.answer is a zero-based index into options[]
- All id fields use kebab-case

Output only valid JSON — no markdown fences, no explanation.
